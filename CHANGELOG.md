# Release Notes

## [Unreleased](https://github.com/Refactor-Circus/Roster/commits/main)

### Breaking

- **SSO and SCIM moved to refactor-circus/guardian.**

  **Without Guardian, organizations that enforce SSO accept password sign-in.** Roster registers no sign-in requirement of its own any more, so upgrading Roster without installing [`refactor-circus/guardian`](https://github.com/Refactor-Circus/Guardian) turns SSO sign-in and the SCIM endpoints off at once. Roster adds no guard for this; install Guardian in the same deploy.

  Removed from Roster: the `Domains\Sso` and `Domains\Scim` domains (their actions, models, policies, requests, resources, events and services) and `SsoConnectionFactory`; their API routes (`roster.organizations.sso-connections.*`, `roster.sso-connections.*`, `roster.users.sso-identities.index`, `roster.sso-identities.destroy`, `roster.organizations.scim-tokens.*`, `roster.scim-tokens.destroy`), the sign-in routes (`roster.sso.*`), the SCIM 2.0 endpoints (`scim/v2/...`, `roster.scim.*`) and the `scim` route surface; the Atrium `sso` and `scim` organization tabs, the SSO connection page, the SSO identities card on the user page, and their `atrium.roster.sso*` and `atrium.roster.scim-tokens.*` routes, controllers and `ui/sso` views; the ten SSO and SCIM MCP tools (`list-sso-connections-tool` to `revoke-scim-token-tool`) and `Mcp\Concerns\DescribesSsoConnection`; the `roster.sso` and `roster.scim` config sections and the `sso_connections`, `sso_identities`, `scim_tokens`, `scim_users` and `scim_groups` keys of `roster.tables` and `Support\Tables::DEFAULTS`; the `create_roster_sso_tables` and `create_roster_scim_tables` migrations and the SSO/SCIM entries of the two index migrations; the `roster.sso` and `roster.scim` resources and the `roster.sso.view`, `roster.sso.manage` and `roster.scim.manage` permissions; the `scim` `MembershipSource` registration and the `scim_token` audit context; `NotSsoEnforced` with its `sso_required` message and the other `sso*` / `scim*` translation keys; and the `laravel/socialite`, `socialiteproviders/saml2`, `socialiteproviders/microsoft-azure` and `firebase/php-jwt` suggestions, now a single `refactor-circus/guardian` suggestion. Roster keeps the extension seams (`Roster::requireSignIn()`, `externalSignInFor()`, `provisionedStatus()`, `MembershipSources`, `Resources`, `PermissionCatalogue`) and `organizations.provisioned_status`, and drops no table, row or permission.

  Upgrading:

  1. Install `refactor-circus/guardian` in the same deploy as this Roster version (`composer require refactor-circus/guardian`).
  2. **Before running any migrate command**, delete your published copies of `create_roster_sso_tables` and `create_roster_scim_tables`, and never roll them back, because their `down()` drops the tables. Remove the SSO/SCIM keys (`sso_connections`, `scim_tokens`, `scim_users`, `scim_groups`) from published copies of the two index migrations (`add_roster_lookup_indexes`, `add_roster_performance_indexes`), which otherwise ask `Tables` for keys it no longer has.
  3. Publish and run Guardian's migrations, before running `roster:sync-permissions`. Guardian's upgrade migration renames `roster_sso_*` / `roster_scim_*` to `guardian_*` and role grants of `roster.sso.*` / `roster.scim.*` to `guardian.sso.*` / `guardian.scim.*`; it acts only once this Roster version is installed (Guardian's handover gate). **If you installed Guardian before this Roster version**, its upgrade migration already ran and skipped, so run `php artisan guardian:upgrade-from-roster` after upgrading Roster to finish the rename.
  4. Move published config from `roster.sso.*` / `roster.scim.*` / `roster.tables.sso_*|scim_*` to the matching `guardian.*` keys, and check that Guardian's SCIM prefix matches what your identity providers call (Roster's default was `scim/v2`).
  5. Replace `RefactorCircus\Roster\Domains\Sso|Scim\…` classes, `roster.sso.*` / `roster.scim.*` route names and permission names (`@rosterCan`, seeders) with Guardian's.
  6. Replace `NotSsoEnforced` with `RefactorCircus\Roster\Support\Rules\NoExternalSignIn` (one `use` change; message key `external_sign_in_required`, with the same English text).

  After upgrading:

  - Old `?tab=sso` and `?tab=scim` links open the organization's default (members) tab. Guardian's tabs are `guardian.sso` / `guardian.scim`.
  - Without Guardian, the five tables and their rows stay untouched, SSO sign-in and the SCIM endpoints answer 404, the three permission rows and their `admin` grants are kept and reported as unregistered by `roster:sync-permissions`, and members who joined through SCIM show their raw stored source, `scim`.
  - The entries below that describe Roster's own `Domains\Sso` / `Domains\Scim` using the seams were written before this move; this entry supersedes them.
- **Roster no longer requires `refactor-circus/atrium`; require it to keep the dashboard** (`composer require refactor-circus/atrium`). Atrium moved to `suggest`. Without it the `atrium.roster.*` routes (`atrium.roster.users.index`, `atrium.roster.organizations.show`, ...) are not registered, so `route()` calls to them throw; Roster's Actions, HTTP API, MCP server, invitation page and impersonation banner work as before. Upgrading:
  - **Atrium's screen registry replaces Roster's tab registry.** `RefactorCircus\Roster\Atrium\Tabs`, `TabDefinition` and `TabVisibility`, their container bindings, and the `ui/partials/tabs` and `ui/partials/registered-tab` partials are removed. Every Roster dashboard screen now declares itself to Atrium's screen extensions registry (`roster.users`, `roster.user`, `roster.organization`, `roster.team`, `roster.role`, `roster.transfer`, `roster.invitation` and the others listed under "Screen extensions" in the README), so tabs and sections can be added to any of them. Re-register a tab from `boot()` with `Atrium::screens()->tab('roster.organization', TabDefinition::make('acme.orders')->...)` (it was `app(Tabs::class)->organization(...)`) or `->tab('roster.user', ...)` (it was `->user(...)`), using `RefactorCircus\Atrium\Domains\Screens\Data\TabDefinition`, whose `label()`, `icon()`, `view()`, `component()`, `resolve()`, `permission()`, `authorize()` and `public()` work as before. `permission()` is checked by the new `ScreenAccess::allowsOn()`, in the same scope as before. In tests, use Atrium's `ResetsScreenExtensions` instead of `app(Tabs::class)->flush()`.
  - **Changed view variables and closure signatures.** A tab view receives `screen`, `record` and `tab` over the resolver's data, no longer `organization` / `user`, `tabs` or `registeredTab`; a component receives only the `data` prop, no longer the record prop. Closures are `authorize(fn (Request $request, ?Model $record, Screen $screen): bool)` and `resolve(fn (?Model $record, Screen $screen): array)`; two- and one-argument closures still work. The organization and user tab bars are Atrium's `x-atrium::screen-tabs`: it shows only with two or more visible tabs and keeps the query string (except `page`) in its links; the built-in `data-testid="tab-{key}"` ids are unchanged.
  - **Registered tab keys.** A registered tab named like a built-in tab is skipped and reported per request instead of throwing at registration. On the organization screen every built-in key (`members`, `teams`, `invitations`, `roles`, `sso`, `scim`, `settings`) is reserved for every viewer, including viewers who may not open that tab, so such a tab shows to no one. A duplicate key throws only in `local` and `testing`; elsewhere it is reported and skipped.
  - **The `activity` and `mcp` organization tabs are removed.** Old `?tab=activity` and `?tab=mcp` links open the organization's default tab (200). `activity` and `mcp` are no longer reserved keys. A record's history now comes from refactor-circus/keen and the MCP screens from refactor-circus/cortex, each registering on Roster's screens through Atrium; install versions of them that do.
  - **The MCP redirect domains UI is removed**: the `RefactorCircus\Roster\Atrium\RedirectDomains` class, `RedirectDomainUiController`, the redirect-domains card on the user page and the `ui/partials/redirect-domains` partial, and the routes `atrium.roster.organizations.redirect-domains.store`, `atrium.roster.organizations.redirect-domains.destroy`, `atrium.roster.users.redirect-domains.store` and `atrium.roster.users.redirect-domains.destroy`. Cortex keeps the domains (Roster never stored them, so nothing is lost) and offers the screens itself. The `mcp`, `redirect_domains`, `redirect_domains_hint` and `no_redirect_domains` translation keys are gone.
  - **Audit trails and the History navigation item are removed.** Roster's user, team and role pages and the organization's activity tab no longer render `<x-atrium::audit-trail>`, and Roster's sidebar group no longer has the **Audit log** link to `/atrium/history/roster`; Keen adds history to Roster's screens itself.
  - **Published views.** If you published `roster-views`, re-publish them (`php artisan vendor:publish --tag="roster-views" --force`). Every screen view changed. The invitation page and impersonation banner moved under `ui/` (`ui/invitations/show`, `ui/impersonation-banner`), used while Atrium is installed, and plain versions replaced them at `invitations/show` and `partials/impersonation-banner-plain`; `@include('roster::impersonation-banner')` still picks the right one. The invitation page now renders through the bindable `Domains\Invitation\Contracts\InvitationPage`.
  - **Old Atrium versions are refused.** `composer.json` declares a `conflict` with `refactor-circus/atrium` `<0.1.0`: v0.1.0 is the first Atrium with the screen extensions registry. A `dev-main` Atrium is not version-checked by Composer, so update it to a `main` that includes the screen extensions registry and `Screen::reserve()`.
  - `@rosterCan` is registered only while Atrium is installed (it is used by Roster's Atrium views).
- **`Roster::ssoRequiredFor()` is removed.** SSO enforcement is now a sign-in requirement (`Domains\Sso\Services\SsoSignInRequirement`), registered by the SSO domain like any other package's, and `NotSsoEnforced` enforces every registered requirement.
  - Upgrading: replace `Roster::ssoRequiredFor($email)` with `Roster::externalSignInFor($email)`. It answers an `RefactorCircus\Roster\Data\ExternalSignIn` (`key`, `label`, `url` where the sign-in starts, and `record`) or null, so `ssoRequiredFor($email)?->is($connection)` becomes `externalSignInFor($email)?->record?->is($connection)`, and the connection itself is `->record`. Super-admins still get null. A registered requirement that throws is not caught: the sign-in fails and the exception is reported.
- **SSO and SCIM authorization moved into their domains.** `Authorizer::RESOURCES` keeps only the core resources (`users`, `organizations`, `members`, `teams`, `invitations`, `roles`), and `BuiltInRoles::PERMISSIONS` drops `roster.sso.view`, `roster.sso.manage` and `roster.scim.manage`: the SSO and SCIM domains register their resources, permissions (granted to `admin`) and policies themselves. Permission names, grants and behaviour are unchanged. The published `config/roster.php` `policies` no longer lists `SsoConnectionModel`, `SsoIdentityModel`, `ScimTokenModel`, `ScimUserModel` or `ScimGroupModel`; a copy that still lists them keeps working, and its entries still win.
  - Upgrading: code that read `Authorizer::RESOURCES['sso']` / `['scim']` or the three permissions from `BuiltInRoles::PERMISSIONS` reads `app(Resources::class)->model('roster.sso')` and `app(PermissionCatalogue::class)->all()` instead.
- **The SCIM token audit context comes from the SCIM domain.** `Support\Audit::context()` keeps `impersonator` and `transfer`; the SCIM domain registers `scim_token` on refactor-circus/keystone's `AuditHooks` itself, for Roster's entries only. Entries record the same `scim_token` (`id`, `name`) as before.
- **`memberships.source` is a string, and membership sources are open to other packages.** `MembershipModel::$source` now reads as the stored string (`'direct'`, `'scim'`, ...) instead of a `MembershipSource` case. The `MembershipSource` enum keeps Roster's built-in sources only (`direct`, `invitation`, `domain`, `personal`, `import`) and loses `Scim`: the SCIM domain registers `scim` (label "SCIM") on the new `Domains\Organization\Services\MembershipSources` singleton, where other packages add theirs with `register($source, $label)` from a provider's `boot()`. `MemberResource` (the API member list and the MCP member tools) shows a registered source's label, otherwise the stored value (so SCIM-provisioned members now show `SCIM` there, where they showed `scim`; built-in sources still show their value), and its output schema declares `source` as a plain string with no enum. Joining code that uses `ManagesMemberships::join()` may pass a registered source as a string; an unregistered one throws `InvalidArgumentException`. Stored rows are unchanged and need no migration.
  - Upgrading: use `$membership->sourceEnum()` where you need the enum; it answers the built-in case, or null for `scim` and any other non-built-in source. Comparisons such as `$membership->source === MembershipSource::Direct` no longer fail loudly: they now silently evaluate false. A `match ($membership->source)` over enum cases throws `UnhandledMatchError`, and `$membership->source->value` fails on a string. Replace `MembershipSource::Scim` with the string `'scim'`. A stored source that nothing registers (a package you removed, say) displays raw, as its stored value, and never errors. Assigning a built-in case (`'source' => MembershipSource::Direct`) still works.
- **Roster has no audit code of its own any more.** Auditing happens only while refactor-circus/keen is installed, and can be turned off with the new `roster.audit.enabled` config key; `Roster::auditing()` says whether it is on. Without it, Roster registers no audit hooks and no `viewAuditLog` ability, offers no history tool (on its MCP server or to Cortex), shows no history in Atrium, and `GET /roster/history` answers 404.
  - Removed: `Roster::audit()` (record your own events with `Keen::record()`), `AuditLogNotInstalledException`, and the legacy `roster_audit_entries` / `roster_audit_chain` migration with its `roster.tables` keys. Installs that already have those tables keep them; copy any old entries into Keen with `php artisan keen:import-roster` before dropping them.
- **Actions take their input as Data objects instead of arrays.** Every Action that took an `array $data` or `array $filters` now takes a typed, immutable `{Action}Data` from its domain's `Data` namespace (`SuspendUserAction` → `Domains\User\Data\SuspendUserData`), built on refactor-circus/keystone's `Data`. Build one from untrusted input with `XData::from($input)`, which validates it (throwing `ValidationException`) and casts each snake_case key to its typed field; from input already validated against `XData::rules()` (as Roster's API and MCP requests do, in one pass with their own rules) with `XData::fromValidated($validated)`; from your own values with `new XData(...)`. `Action::rules()` moved to `XData::rules()`, with the same context arguments. Partial updates leave fields out as `Keystone\Data\Missing`, so a field set to null stays apart from one not sent (`$data->has('email')`). Action events that carried the input array (`UserCreatingActionEvent::$data`, `UsersListingActionEvent::$filters`, ...) carry the Data object. `ApproveUserAction` and `ReactivateUserAction` no longer take an (unused) array, and no-input Actions lost their empty `rules()`. Requires refactor-circus/keystone with `Data`.
- Moved to the Refactor Circus organisation: the package is now `refactor-circus/roster` with the PHP namespace `RefactorCircus\Roster` (it was `jayi/roster` and `JayI\Roster`). Update `composer.json` requirements and `use` statements. Old class names are not kept as aliases, so stored values written under them - polymorphic `*_type` columns, audit subjects, Pennant feature names - need updating to the new names.

### Added

- **Screen extensions on every Roster screen.** With refactor-circus/atrium installed, each Roster dashboard screen (users, organizations, teams, roles, permissions, impersonations, imports and exports, and the invitation page) declares itself to Atrium's screen extensions registry, so apps and packages add their own tabs and sections (`header.actions`, `before`, `after`, `aside` on a record's page, `row.actions` in each list row) from `boot()` with `Atrium::screens()`, shown only to those allowed through a Roster `permission()` (checked by the new `ScreenAccess::allowsOn()`), an `authorize()` closure or an explicit `public()`. See "Screen extensions" in the README.
- **Extension seams for other packages.** Packages add to Roster from a provider's `boot()`, and Roster's own SSO and SCIM domains use the same seams. See "Extending Roster" in the README.
  - `Domains\Permission\Services\Resources::resource($prefix, $model)`: the model's Gate policy answers permissions named `{prefix}.{verb}` in every Roster check (API, MCP, `ScreenAccess`, `@rosterCan`). A registered model without a policy throws `InvalidArgumentException` naming the resource on first use.
  - `Domains\Permission\Services\PermissionCatalogue::permission($name, $description, $grantTo)`: system permissions, created by the role migration, `BuiltInRoles::sync()` and `roster:sync-permissions`, and granted to the named built-in roles only when the sync creates them. Existing roles never gain them automatically. `roster:sync-permissions` now warns about system permissions nothing registers, and keeps them.
  - `Domains\Organization\Services\MembershipSources::register($source, $label)`, with `MembershipModel::sourceEnum()`.
  - `Contracts\SignInRequirement`, registered with `Roster::requireSignIn()` and asked with `Roster::externalSignInFor($email)`.
  - `Roster::provisionedStatus($organization)`: the status SSO, SCIM and other provisioned accounts start with. An invalid stored `provisioned_status` falls back to active and is reported, so provisioning never fails and the bad value is never silent.
  - `roster.*` resource prefixes and permission names are reserved for Roster's own domains: registering one through `resource()` or `permission()` throws.
  - Audit context is not a Roster API: packages register on refactor-circus/keystone's `AuditHooks`, as the SCIM domain does.
- **Configurable statuses, and statuses on organizations and teams.** The new `roster.statuses` config key names the string-backed enum each record's status uses: `users` (implementing the new `Contracts\AccountStatus`, which names the cases the approval, suspension and deactivation flows use and whether a status `allowsAccess()`), `organizations` and `teams` (implementing `Contracts\Status`: label, Atrium badge, default). Organizations and teams gain `status`, `status_reason` and `status_changed_at` (new migration; existing rows take the configured default), defaulting to the new `OrganizationStatus` / `TeamStatus` enums (`active`, `inactive`). Set them through the create, update and sync Data (`status`, `status_reason`), the API, MCP tools and Atrium's Settings forms; filter lists by `status`; read them in the organization and team resources. They are stored and shown only: Roster grants and refuses nothing by them. `Support\Statuses` resolves the configured enums.
- **MCP output schemas.** Every tool that answers with structured content declares an `outputSchema()`, built from its resource's new `schema()` (fields, types, nullability and enum values), so agents know the shape before calling. Responses come from the resources' `toStructuredResponse()` (refactor-circus/keystone's resource base, which every Roster resource now extends); the payloads are unchanged. The `respondWith…()` helpers on the MCP request bases are gone.
- **Configurable policies for every model**, registered with the Gate from the new `roster.policies` config key (one bundled policy per model, in each domain's `Policies` namespace, on `Support\Policies\Policy`). Roster's API, MCP tools and Atrium screens now ask them: permission `roster.{resource}.{verb}` is answered by the policy of the resource's model, by the camel-cased verb (`roster.users.manage-status` asks `UserPolicy::manageStatus()`), with the model's class, the organization or team in scope and the user the call is about. The bundled policies answer with Roster's permissions, so behaviour is unchanged until a policy is swapped. `Authorizer::permits()` is the permission-only check they use.
- **Configurable table names**: every table, pivot included, is named under the new `roster.tables` config key and read by the migrations, models, validation rules and queries through `Support\Tables`. Keys a published config leaves out keep their default.
- **Model lifecycle events**: every model dispatches a class-based event for each Eloquent hook (`TeamCreatingEvent`, `OrganizationTrashedEvent`, ...; the soft-delete hooks on `OrganizationModel` and `UserModel`), implementing Keystone's `ModelLifecycleEvent`.
- Starting and finished events for the CSV import and export steps: `ImportValidatingActionEvent` / `ImportValidatedActionEvent`, `ImportRowApplyingActionEvent` / `ImportRowAppliedActionEvent` (per row, as the confirmer), `ExportBuildingActionEvent` / `ExportBuiltActionEvent` and `TransferFinishingActionEvent` before the existing `TransferFinishedActionEvent`. With refactor-circus/keen installed, a confirmed import now also records one entry per row.
- The package's section in Atrium's sidebar rail has its own icon (`user-group`) and a fixed place in the rail.

### Changed

- User statuses go through the configured enum: `Users::status()`, `HasRoster::rosterStatus()` and the profile's `status` are typed `Contracts\AccountStatus` (the default `UserStatus` implements it), and the `roster.active` middleware, impersonation and SSO ask `allowsAccess()` instead of comparing with `UserStatus::Active`. `CreateUserData::$status` and `CreateOrganizationData::$provisionedStatus` default to null, meaning the enum's `active()` case. `Badges::forStatus()` takes any `Contracts\Status` and uses its `badge()`.
- `Support\Tables` extends refactor-circus/keystone's `Database\Tables`; `Tables::name()` and `Tables::DEFAULTS` are unchanged. The architecture tests now fail on a table named as a literal string and on a model without a policy in `roster.policies`.
- `ImportRowApplyingActionEvent` / `ImportRowAppliedActionEvent` implement refactor-circus/keystone's `UnauditedActionEvent`, so Keen no longer writes an audit entry per import row; the Actions each row runs are still recorded. Import validation writes the planned rows in batches, each in its own short transaction, rather than holding one write lock for the whole file; the transfer only becomes confirmable with the final report.
- The shared history route (`GET /roster/history`) answers guests 401, like Roster's other routes; refactor-circus/keystone's request base now does this for every package. The plain `{"message": "Not found."}` 404 for missing records on Roster's routes now comes from Keystone too: its message is the JSON-translatable `Not found.`, and the `roster::roster.not_found` translation key is gone (remove it from published language files).
- **Every write happens in a transaction**, the CSV transfer's too: cancelling and confirming a transfer and each import/export step (validating, applying a row with its recorded result, building, finishing, closing) now commit their writes together, so a failed step leaves nothing half-written, and its finished event fires only once they commit. Impex is signalled after Roster's write commits.
- Internal tidying with no change to routes, tools or payloads: the HTTP and MCP request bases share one authorization trait, organization requests are scoped to their organization by default, each MCP base declares its identifier rules once, deleted users and organizations are found by the request bases, and the Atrium controllers share `actor()` and the organization lookup.

- **Organizations are purged in the background.** `DELETE /roster/organizations/{organization}/purge`, the MCP purge tool and Atrium's Danger zone check the request at once, then queue a unique `PurgeOrganizationJob` (after commit) and answer **202 Accepted** with a message (it was 204), the tool says it is being deleted, and Atrium says it disappears shortly. `PurgeOrganizationAction::queue()` does the same from code; `execute()` still purges in place. `roster:purge-deleted` queues one job per organization, so one failure no longer stops the run. Needs a queue worker. An organization restored before its job runs is kept.
- **`roster:end-expired-impersonations`** ends impersonations whose time ran out but whose impersonator never came back, and one-time links never used, as `expired` through `StopImpersonationAction`, so the audit log records the end. Schedule it.
- **Notifications are queued, and sent only after the change commits**: the invitation email, the approvers' "waiting for approval" email and the approved/rejected emails. Mail no longer slows or fails the request, and a change that rolls back (a failed SCIM call, an SSO sign-up that fails later) sends nothing. Run a queue worker; with the `sync` queue they still go out at once.
- **Faster permission checks**: each user's role assignments load in one query per request, and every organization, team and permission after that is answered in memory (five permissions checked across ten organizations went from 23 queries to at most 4, however many organizations). The permission caches are kept across actions that cannot change access (SSO, SCIM tokens, transfers, other packages' actions), so bulk work no longer rebuilds them for every row.
- **Faster SCIM group updates**: a group PATCH, as Okta and Entra send for every membership change, no longer builds the group a third time for a version check nobody asked for (`If-Match`), and syncs members in a fixed number of queries whatever the group's size (it used one per member).
- **Faster imports**: applying a member row reuses what its preview looked up (about 27 queries a row, down from about 40), and an organization row is built once and not reloaded.
- New indexes on the columns Roster looks up by that no index led with (organization ids on domains, roles, SSO connections, SCIM tokens and groups, transfers and impersonations; profiles' current organization and team; organization names; impersonation dates). The migration skips any index that already exists (MySQL indexes foreign keys itself). Run `php artisan migrate`.
- **Email lookups use the email index.** Finding a user by email (SSO sign-in, SCIM provisioning, invitations, imports, `roster:grant-super-admin`) first tries the address as given and lowercased with a plain equality, and only on a miss compares case-insensitively; on PostgreSQL that comparison (and SCIM `eq` filters) is `lower(column) = ?` instead of an `ILIKE` full scan. PostgreSQL apps can add the matching expression index with the new opt-in `roster-email-index-migration` publish tag. `Users::findManyByEmail()` looks up a batch at once.
- **Import previews look up a batch of rows at once**: the members, users and organizations planners prefetch accounts, memberships with seats, organization roles, pending invitations, owners and links for each 500 rows (new `Planner::prefetch()` hook), so previewing no longer costs two or more queries per row. Applying a row still plans against the state at that moment.
- **Bulk organization sync** (`SyncOrganizationsAction`) looks up every record's link with its organization and domains up front and stamps unchanged links' `synced_at` in one update. `SyncOrganizationAction::execute()` / `preview()` take the prefetched `link` (and `execute()` a `touch` flag); `SyncOrganizationAction::links()` does the lookup.
- **Permission caches forget less**: a finished action that changes only one user's access (role assigned or revoked, joining or leaving an organization or team, switching context, user status changes) forgets only that user's answers, and the permission names are reloaded only when a permission changes (`Permissions::flush(bool $catalogue = true)`, `Permissions::flushUser()`). `Authorizer::check()` remembers each answer for the request, and policies asked with records find the record's organization or team once per request by key (`Authorizer::parentOf()`) instead of lazy-loading it on every record; eager-load `organization` / `team` on lists you check record by record.
- **Optional cross-request permission cache**: set `roster.permission_cache.ttl` (seconds; 0, the default, keeps it off) and optionally `roster.permission_cache.store` to keep the permission names and each user's role grants in the cache store, so a request's first check skips their queries. Roster's Actions and model writes clear it; call `Permissions::forgetCache()` after writing roles, assignments or permissions some other way.
- New composite indexes on `(organization_id, created_at, id)` for memberships, role assignments, invitations, SCIM users and SCIM groups, the order their organization lists page in. Run `php artisan migrate`.
- Atrium: the global search matches users and organizations from the start of a name, email or slug (it matched anywhere, which no index can serve); the Users and Organizations screens' own filters still match anywhere. The user-status widget's counts are cached for a minute and forgotten whenever a Roster user action finishes. The team page pages through its members (25 at a time) and loads the add-member picker only for those who may add.
- `ShowTeamAction` (the team API, MCP tool and Atrium page) carries at most the first 100 members, oldest first (`ShowTeamAction::MEMBERS`); `members_count` is still the full count. List all of a team's members a page at a time with the members list's new `team` filter (`GET /roster/organizations/{organization}/members?team={slug}`, the `team` argument of the list-members tool, `ListMembersData::$team`).
- `AssignRoleData::$organization` also takes the `OrganizationModel`, saving a lookup (member imports pass it).
- Smaller savings: a user's current organization and team resolve in one query each, the Atrium user page offers only shared roles and the user's organizations' roles (it loaded every role), role-assignment lists load each team's organization with them, the audit hooks reuse a loaded organization, and domain auto-join responses load owners up front.

- Roster's permission checks for users, organizations, members, teams, invitations, roles, SSO and SCIM go through the Gate (see the policies above), so an application's `Gate::before` callbacks now apply to them. Permissions blocked while impersonating are still refused before the Gate is asked.
- Requires PHP 8.5 (`php: ^8.5`); CI and the browser tests run on PHP 8.5 only. Dependency floors raised to the current releases: laravel/framework ^13.35, orchestra/testbench ^11.3, pestphp/pest ^5.3.1, pestphp/pest-plugin-browser ^5.1.2 and larastan/larastan ^3.13; Playwright ^1.64.

### Breaking

- **The audit log moved to [`refactor-circus/keen`](https://github.com/Refactor-Circus/Keen)**, the suite-wide audit log; install it (`composer require refactor-circus/keen`, suggested) to keep recording. Roster's audit domain is gone: `Domains\Audit` (`AuditRecorder`, `AuditLog`, `Snapshots`, `Surface`, `PendingAuditEntry`, `AuditEntryModel`, its actions, events, requests, resources and policy), the `/roster/audit` API routes, the `list-audit-entries-tool`, `show-audit-entry-tool` and `record-audit-event-tool` MCP tools, the Atrium Audit log screens and navigation item, the `roster:prune-audit` and `roster:verify-audit` commands (use `keen:prune` and `keen:verify`), the `roster.audit` config block (`keen.redact`, `keen.retention_days` and `keen.enabled` replace it), the `export_audit` transfer type and its `AuditExporter`, and the `roster.audit.record` permission. The `roster_audit_*` tables and their migration stay: copy existing entries into Keen once with `php artisan keen:import-roster`. Delete old transfers of type `export_audit` when upgrading, since Roster can no longer read them (their rows cascade): `DB::table('roster_transfers')->where('type', 'export_audit')->delete();`.
- Roster registers what it knows on refactor-circus/keystone's `AuditHooks` instead, whether or not Keen is installed (`Support\Audit`): labels for users, organizations, teams, roles, invitations, role assignments and transfers; profile fields, role permissions, organization domains and assignment slugs in the diffs; role assignments and impersonations recorded about the user; the organization as each entry's scope (a user's current organization for changes to the user alone); the impersonator, CSV import and SCIM token as context; and the users' password column redacted. SCIM routes record as surface `scim`, the signed invitation and impersonation pages as `web`. If the app has not defined the `viewAuditLog` Gate ability, Roster defines it as the global `roster.audit.view` permission.
- `Roster::audit()` is deprecated: it returns Keen's pending entry (`->save()` rather than `->record()`), and throws `RefactorCircus\Roster\Exceptions\AuditLogNotInstalledException` without Keen. Use `Keen::record()`.
- The Atrium user Activity card and organization Activity tab now show the record's history from Keen through `<x-atrium::audit-trail>`, as do the team and role pages; the organization tab is offered only while Keen is installed. (Since removed: Keen adds history to Roster's screens itself, see the first Breaking entry above.)
- Roster ships no stylesheet and no Blade component namespace: `resources/css/atrium.css` and the `x-roster::` components are gone, and every view uses Atrium's components and safelisted utilities only. Include the impersonation banner with `@include('roster::impersonation-banner')` instead of `<x-roster::impersonation-banner />`; it is Atrium's standalone banner, styled inline for the app's own pages. The invitation page uses Atrium's guest layout. Published views must be republished.
- `RosterPlugin::features()` uses Atrium's shared `featuresFromConfig()`.

- Roster now stands on [`refactor-circus/keystone`](https://github.com/Refactor-Circus/Keystone), the shared runtime of the Refactor Circus suite, which it requires. Its local copies are gone in favour of Keystone's: `RefactorCircus\Roster\Contracts\ActionStartingEvent` / `ActionFinishedEvent` → `RefactorCircus\Keystone\Contracts\*` (listen there; the contracts are shared by every Refactor Circus package), `Support\ServiceProvider` → `RefactorCircus\Keystone\Support\ServiceProvider`, `Mcp\Tool` → `RefactorCircus\Keystone\Mcp\Tool`, and `Cortex\CortexIntegration` → `RefactorCircus\Keystone\Cortex\CortexIntegration::for($package)`. `RosterServiceProvider` extends `PackageServiceProvider` and registers the package as `roster`; `RosterServer` extends `RefactorCircus\Keystone\Mcp\Server`; `Http\Request` and `Mcp\Request` extend Keystone's request bases and keep Roster's own permission checks. Finished Action events now dispatch after the surrounding transaction commits, so listeners never hear about rolled-back work. Config keys, route names, permissions and tool names are unchanged.

- The package is reorganised into domain modules (`src/Domains/User`, `Organization`, `Team`, `Invitation`, `Role`, `Permission`, `Audit`, `Impersonation`, `Sso`, `Scim`, `Transfer`), mirroring the mono application's layout. Config keys, route names and paths, MCP tool names, publish tags, views, translations, the `@rosterCan` directive, tables and event class names are unchanged. Package-wide pieces keep their names: `RosterServiceProvider`, the `Roster` class and facade, `RosterPlugin`, `Badges`, `CortexIntegration`, the event contracts, `Http\Request`, `Http\Controllers\TrashController`, `Console\Commands\PurgeDeletedCommand`, `Mcp\Request`, `Mcp\Tool`, `Mcp\RosterServer` and `Support\Users`/`Scopes`/`Slugs`/`UserKey`. ### Fixed

- `roster:purge-deleted` and `roster:prune-transfers` skipped records once more than a thousand matched: they paged by offset while removing the rows they paged over. They page by id now.
- An invitation whose email failed to send could never be sent again: the invitation was saved, the request failed, and a retry was refused as already pending. The email is now queued after the invitation commits, and retried by the queue.
- List Data classes and their MCP tools take their paging from one `pagination()` definition (refactor-circus/keystone's `Pagination`), so the validation rules and the tool's `per_page`/`page` schema state the same limits and default. A `per_page` of null now falls back to the default instead of failing validation.
- `list-permissions-tool` described its page size as 1-100 while accepting up to 200; the role list tools now state their 1-100 limit in their schema too.

- Roster's audit log records only Roster's own Action events, now that the event contracts are shared with other Refactor Circus packages.

- An organization's tabs each need their own permission there (`roster.members.view`, `roster.teams.view`, `roster.invitations.view`, `roster.roles.view`, `roster.sso.view`, `roster.scim.manage`, `roster.audit.view`). Before, anyone who could view the organization could open every tab, including SCIM tokens, SSO connections and its audit log.

### Added

- `GET /roster/history` (`roster.history.index`) and `list-roster-history-tool`, the suite-wide history endpoint and tool from refactor-circus/keystone. They need `roster.audit.view` globally and read [`refactor-circus/keen`](https://github.com/Refactor-Circus/Keen)'s shared audit log; until it is installed they answer that no audit log is installed (404 over HTTP).
- Changes made by Cortex agents through Roster's tools are recorded with surface `cortex`.

- Atrium screens use icon-only buttons and tabs (labelled, with a tooltip), status dots instead of status badges (pending - users, invitations, transfers awaiting confirmation - has its own colour), and icons on Roster's navigation items.
- Organization admins can open the organizations, roles, impersonations, transfers and audit lists, in Atrium, over the API and MCP, limited to their own organizations, and see the matching Atrium navigation. Organization search is limited the same way.
- Atrium pages show only the controls the viewer may use, checked exactly as the action behind each one is (permission, organization or team, and "about yourself"), through the new `@rosterCan` Blade conditional.
- `roster.atrium.features`: feature flags that switch Roster in Atrium on and off as a whole, through Atrium's feature resolver. Defaults to `RosterSupportFeature`, an overridable PennantPlus feature that is on until its global value is set; skipped without refactor-circus/pennantplus.

- Users + profiles: user CRUD on the host's own user model (trait, trait-less, or the bundled `RefactorCircus\Roster\Models\User`), with configurable key type and column mapping.
- `roster_profiles` table with display name, avatar, timezone, locale, bio and meta.
- Active / suspended / deactivated status with Suspend, Deactivate and Reactivate Actions, plus the `roster.active` middleware.
- JSON API and MCP server for every Action, both disabled by default.
- Atrium plugin: Users screens, a status widget and user search.
- Organizations with teams and members, single owner with transfer, and optional personal organizations.
- Email invitations (optionally onto teams) with a signed, auth-protected accept page; only the invited email can accept.
- Per-organization domain auto-join, for verified emails only.
- Current organization/team context (`SwitchContextAction`, `currentOrganization()`, `currentTeam()`) and the `roster.organization` middleware.
- HTTP, MCP and Atrium surfaces for all of the above.
- Roles and permissions in the database, at global, organization and team scope; shared and organization-specific roles; built-in `super-admin`, `admin`, `member` and `lead` roles.
- Laravel Gate integration (`$user->can()`, `@can`); Atrium's `viewAtrium` gate defaults to the `atrium.view` permission.
- `roster:grant-super-admin` and `roster:sync-permissions` commands; `roster.super_admins` config (verified emails only).
- Authorization on every API route, MCP tool and Atrium screen (`roster.authorization`, on by default), with a privilege-escalation guard on role grants.
- Cortex integration: when `refactor-circus/cortex` is installed, the MCP server and every tool are registered with it, with publishable instruction and description overrides (`roster.cortex`).
- `throttle:roster` rate limiter on the API and MCP (`roster.rate_limit.per_minute`, default 120).
- Missing records on Roster routes answer `404 {"message": "Not found."}` without naming model classes.
- Workbench demo (`composer serve`) and Atrium browser tests (`composer test:browser`).
- Audit log: every Roster change recorded with actor, surface, organization and field diffs (secrets redacted); append-only and hash-chained, with `roster:verify-audit` and `roster:prune-audit`.
- Impersonation: `roster.users.impersonate` permission, one-time signed links usable only by the impersonator, required reason, time limit, `<x-roster::impersonation-banner />`, blocked abilities (`roster.impersonation.blocked`, enforced through the Gate too), locked email/password, and audit entries naming the real actor.
- Single sign-on per organization: OpenID Connect (id_token verified against JWKS), Microsoft Entra ID (`socialiteproviders/microsoft-azure`, single-tenant only, UPN-based), and SAML 2.0 (`socialiteproviders/saml2`). Just-in-time accounts and auto-linking are limited to the organization's domains; optional enforcement through `NotSsoEnforced` / `Roster::ssoRequiredFor()`; encrypted, never-serialized secrets. The protocol packages are optional (`suggest`).
- SCIM 2.0 provisioning per organization (`/scim/v2/{organization}`): Users map to members and Groups to teams; filters, PATCH (Okta and Entra shapes), Bulk, ETags and discovery endpoints. Per-organization bearer tokens are hashed, expirable and revocable. Deprovisioning removes the membership and deactivates only orphaned SCIM-created accounts, never deleting anything. Optional SSO subject linking via `externalId`.
- CSV import and export through `refactor-circus/impex` (optional, `suggest`):
  - Import members, users and teams; export members, users and the audit log.
  - Imports are validated into a per-row preview (create / link / invite / update / skip / error). Nothing changes until confirmed.
  - Confirmed rows are applied as the confirmer, with their permissions re-checked. Errors are reported per row.
  - Unconfirmed imports expire.
  - No password column is accepted, and emails outside the organization's domains become invitations.
  - Exports neutralize spreadsheet formulas and download through an authorized route; MCP gets 15-minute signed links.
  - Files are pruned by `roster:prune-transfers`.
  - Available over HTTP, MCP and Atrium (Imports & exports).
  - Downloadable CSV templates for every import type (header plus `#` comment examples, which imports skip), publishable with the `roster-import-templates` tag. Imports with no rows are refused.
- Organization sync from external systems (ERP, CRM, …):
  - `SyncOrganizationAction` upserts by `source` + `external_id`, writing only the fields sent; `SyncOrganizationsAction` handles bulk, with per-record results.
  - Per-source links (`roster_organization_links`) hold the external id, account number and last sync time. Manage them with `LinkOrganizationAction` / `UnlinkOrganizationAction`, and filter organizations by them.
  - `import_organizations` CSV import type, and an `export_organizations` export in the same columns (optionally one source's records) that imports straight back.
  - New global `roster.organizations.sync` permission.
  - Available over HTTP, MCP and Atrium (Settings tab, list filters).
- Soft deletes:
  - deleted organizations, and users on models using `SoftDeletes` (the bundled model does), go to Deleted with everything kept;
  - a deleted organization is switched off (pages, API, SSO, SCIM, auto-join), with its slug and domains reserved;
  - restore and purge Actions, routes, MCP tools and Atrium screens, with new `roster.users.purge` / `roster.organizations.purge` permissions;
  - `roster:purge-deleted` with `roster.deletes.retention_days` (null keeps forever).
- User approval:
  - a `pending` status with `ApproveUserAction` / `RejectUserAction` (`roster.users.approve`);
  - the starting status is set by `roster.users.registration_status` for self-registration, by a `status` choice when admins create users, and by an organization's `provisioned_status` for its SSO and SCIM accounts;
  - approval emails for approvers and users, each switchable;
  - pending users are blocked by `roster.active` and SSO sign-in.
- Performance:
  - Gate checks without a scope resolve the current organization/team once per request (20 checks: 125 → 9 queries).
  - API user lists and SCIM user pages cost a fixed number of queries whatever their length.
  - The organization page loads and paginates only the open tab.
  - CSV imports cache organization data per run and keep row results in `roster_transfer_rows` (paged with `rows_page`), and exports batch their lookups.
  - New indexes.
- Atrium search: users and organizations are two sources, each with its own result quota and a description for Atrium's classification, and both work under Atrium's process driver (requires Atrium with multi-source plugins).
- SCIM: `eq` filters match in place inside the organization, and Groups pages load their members in fixed queries.
- Fixed: `Authorizer` could keep one request's permissions in long-lived workers (Octane, queues).
- Fixed: concurrent audit writes could fork the hash chain on Postgres; appends now lock a chain-head row.
- Organizations may have no owner (`owner` is optional when creating); personal organizations still require one.
- `Roster::audit()` / `RecordAuditEventAction` for the app's own events (`source: app`), plus `roster.audit.view` / `roster.audit.record` permissions and HTTP, MCP and Atrium surfaces.
